# Growth Strategy: Level 3 Addendum
## Стратегический горизонт Year 2–3 — Fully Autonomous Intelligence Harness

**Версия:** 1.0  
**Горизонт:** Year 2–3 (Month 18–36)  
**Тип документа:** Аддендум к Growth Strategy, стратегический раздел

---

## Тезис

Level 3 — не техническое упражнение. Это стратегический императив, который меняет природу продукта: из Claude-плагина в автономный AI-продукт со своей моделью, интерфейсом и defensibility. Каждый день работы на Level 1 — это день накопления зависимости от внешнего вендора, который не знает о существовании Frontier Intelligence.

---

## 1. Почему Level 3 — стратегический императив

### 1.1. Dependency Risk: что именно может сделать Anthropic

Сегодня Claude — это интерфейс харнеса. Anthropic может:

**Ценовое давление.** Claude API уже пережил несколько итераций ценообразования. За 2023–2025 стоимость токенов менялась существенно в обе стороны — но структурно тренд на commoditization LLM означает, что Anthropic будет искать другие источники дохода. Enterprise-контракты, API tier ограничения, usage caps для non-enterprise.

**Изменение MCP условий.** MCP (Model Context Protocol) — открытый стандарт, но Anthropic контролирует его развитие. Изменение протокола, введение сертификации MCP-серверов, ограничения на типы инструментов — всё это возможно в течение 2–3 лет. Frontier Intelligence сегодня не имеет рычага влияния на эти решения.

**Feature restriction.** Anthropic может ограничить возможности для конкурирующих use cases. Если Anthropic запустит собственный "intelligence harness" или партнёрство с конкурентом, доступность API может стать условной.

**Terms of Service изменения.** Anthropic неоднократно обновлял ToS. Запрет определённых категорий контента, ограничения на resale/white-label, требования к attribution — всё это операционный риск.

**Вывод:** Frontier Intelligence не может строить долгосрочный бизнес на фундаменте, который не контролирует. Level 3 — это хедж. Не уход от Claude навсегда, а устранение single point of failure.

### 1.2. Margin Imperative

**Текущая структура затрат (Level 1, estimate для 1 000 MAU):**

| Статья | Стоимость/месяц | % от выручки (при $20 ARPU) |
|---|---|---|
| Claude API (inference) | $800–1 500 | 4–7.5% |
| Frontier backend (сервера, GigaChat API) | $400–800 | 2–4% |
| Инфраструктура прочее | $200–400 | 1–2% |
| **Итого COGS** | **$1 400–2 700** | **7–13.5%** |
| **Gross Margin** | **$17 300–18 600** | **86.5–93%** |

На первый взгляд — отличная маржа. Но Claude API стоимость масштабируется линейно с пользователями, а не деградирует. При 10 000 MAU:

| Статья | Level 1 (с Claude) | Level 3 (own LLM) | Разница |
|---|---|---|---|
| LLM inference | $8 000–15 000 | $600–1 500 (Together.ai) | -$7 000–13 500 |
| LLM inference (self-hosted) | — | $800–1 500 | -$6 500–13 500 |
| Amortized fine-tuning | — | $500–1 000 | +$500–1 000 |
| **Итого LLM COGS** | **$8 000–15 000** | **$1 100–2 500** | **Экономия 70–85%** |

При $200K ARR (10K MAU × $20 ARPU) разница в LLM-расходах составляет **$78 000–156 000 в год**. Это прямо в GP.

Level 3 при том же ARR даёт **на 5–10 процентных пунктов больший Gross Margin** — что критически важно для SaaS-мультипликаторов при привлечении инвестиций или продаже бизнеса.

### 1.3. Moat: что меняется в competitive defensibility

**Level 1 moat:** Frontier-бэкенд (алгоритмы кластеризации, источники, качество сигналов) + UX-слой поверх Claude.  
**Проблема:** UX-слой нельзя запатентовать, легко скопировать. Любой конкурент с доступом к Claude API может сделать "похожий Claude wrapper".

**Level 3 moat:** Frontier-бэкенд + **fine-tuned модель, обученная на паттернах взаимодействия реальных пользователей** + собственный интерфейс.

Fine-tuned модель — это flywheel. Чем больше пользователей → больше `harness_interactions` → лучше модель → лучший продукт → больше пользователей. Конкурент, стартующий завтра, не имеет этих данных. Claude wrapper не имеет этого flywheel по определению.

**Два вида moat после Level 3:**
1. **Data moat:** уникальный датасет взаимодействий пользователей с intelligence harness — никто другой его не имеет
2. **Model moat:** fine-tuned модель, специализированная под конкретный продуктовый use case — принципиально другой уровень качества для этой задачи vs generic LLM

## 2. Когда переходить: триггеры Level 3

Level 3 не нужно форсировать. Слишком ранний переход — это distraction от core SaaS growth. Слишком поздний — упущенное окно для дифференциации.

### Триггеры для запуска Фазы A (Data Foundation)

Стартовать параллельно с SaaS при любом из:

- ✅ **500+ зарегистрированных пользователей** (достаточный поток данных)
- ✅ **$5K+ MRR** (есть cash flow на инфраструктуру логирования)
- ✅ **Любое изменение в Claude ToS или ценообразовании** (немедленный триггер)

Фаза A — дешёвая (добавить logging = несколько дней разработки). Нет причин откладывать.

### Триггеры для запуска Фазы B (Own LLM)

Начинать при:

- ✅ **5 000+ harness_interactions** в базе (минимум для первого fine-tune)
- ✅ **$15K+ MRR** (можно выделить $2K–5K на fine-tuning эксперименты)
- ✅ **Команда 3+ человек** (есть кто заниматься MLOps)
- ✅ **Anthropic повышает цены >30%** (немедленный триггер)

### Триггеры для запуска Фазы C (Own Interface)

Начинать при:

- ✅ **Own LLM в production, A/B показывает паритет с Claude** (есть что за интерфейсом)
- ✅ **$50K+ MRR** (есть бюджет на фронтенд-разработку)
- ✅ **Claude вводит ограничения на MCP или Projects** (форс-мажорный триггер)
- ✅ **Запуск мобильного приложения запланирован по продуктовой roadmap**

## 3. Как Level 3 меняет конкурентную позицию

### 3.1. Нарратив для рынка

**Level 1 positioning:** "Frontier Intelligence — это умный AI-агент поверх Claude, который следит за сигналами рынка."  
*Риск: пользователи могут думать "зачем мне это, если у меня есть Claude напрямую?"*

**Level 3 positioning:** "Frontier Intelligence — это персональный intelligence harness с собственной AI-моделью, обученной понимать ваш контекст, ваши решения, ваши вопросы."  
*Позиция: отдельный продукт, не обёртка. Конкурент Perplexity, Elicit, Notion AI — не Claude.*

Это переводит разговор из "AI-инструмент" в "AI-коллаборатор". Разные категории, разные мультипликаторы.

### 3.2. Competitive mapping

| Конкурент | Level 1 Frontier vs | Level 3 Frontier vs |
|---|---|---|
| Perplexity | Frontier глубже в нишевых доменах, но Perplexity масштабнее | Конкурируем напрямую: собственная модель + интерфейс |
| Elicit (research assistant) | Нет прямого пересечения | Выходим в смежную категорию "research intelligence" |
| Notion AI | Нет пересечения | Потенциально конкурируем за "thinking tool" бюджет |
| Claude Projects (Anthropic) | Мы работаем поверх → зависимы | Мы конкуренты → независимы |
| Generic "Claude wrapper" стартапы | Не сильно отличаемся | Принципиальная разница: данные + модель |

**Ключевой сдвиг:** с Level 3 Frontier Intelligence перестаёт быть Claude-экосистемным продуктом и становится независимым AI-продуктом. Это открывает партнёрства, которые были невозможны раньше (например, с OpenAI, Google, Yandex).

## 4. Финансовая логика Level 3

### 4.1. P&L сдвиг: Year 2 vs Year 3

**Сценарий: 5 000 MAU, $20 ARPU = $100K MRR = $1.2M ARR**

| Статья | Year 2 (Level 1) | Year 3 (Level 3) | Δ |
|---|---|---|---|
| **Revenue** | $1 200 000 | $1 200 000 | — |
| Claude API | -$120 000 | -$0 (выключен) | +$120 000 |
| Own LLM inference (Together.ai) | — | -$18 000 | -$18 000 |
| Fine-tuning (amortized) | — | -$6 000 | -$6 000 |
| Frontier backend | -$60 000 | -$60 000 | — |
| Infra прочее | -$30 000 | -$40 000 | -$10 000 |
| **Gross Profit** | **$990 000 (82.5%)** | **$1 076 000 (89.7%)** | **+$86 000** |

**+7.2% Gross Margin** при том же ARR = $86K дополнительной GP в год. При $5M ARR это $360K дополнительной GP ежегодно.

### 4.2. SaaS мультипликаторы и оценка

Инвесторы оценивают SaaS по ARR-мультипликатору, который существенно зависит от Gross Margin:

| Gross Margin | Типичный ARR-мультипликатор (2024–2025) |
|---|---|
| 60–70% | 4–6x |
| 70–80% | 6–8x |
| 80–90% | 8–12x |
| 90%+ | 10–15x |

Level 3 переводит Frontier Intelligence из диапазона 6–8x в 8–12x. При $2M ARR разница в оценке: **$12M–16M (Level 1) vs $16M–24M (Level 3)**. Это не маленькая разница.

## 5. M&A сценарии

### 5.1. Кто покупает "Claude wrapper" vs автономный харнес

**Level 1 (Claude wrapper) — ограниченный M&A appeal:**

- Стратегические покупатели смотрят на user base, не на технологию
- Нет proprietary technology (Frontier-бэкенд интересен, но MCP-интерфейс — нет)
- Вопрос любого покупателя: "Что мы покупаем, если Claude завтра запустит то же самое?"
- Типичный покупатель: медиа-компания или enterprise software хочет AI-фичу, покупает team + user base

**Level 3 (автономный харнес с own model) — высокий M&A appeal:**

- Proprietary fine-tuned модель = технологический актив
- Датасет `harness_interactions` = data asset, который нельзя воссоздать быстро
- Собственный интерфейс = user relationship (не посредники)
- Вопрос покупателя: "Как быстро мы можем масштабировать этот flywheel на нашу user base?"

### 5.2. Потенциальные покупатели при Level 3

**Категория A: Enterprise intelligence platforms**
- Компании типа Crayon, Klue, Contify (competitive intelligence SaaS)
- Им интересна: модель + данные + пользователи + Frontier-бэкенд
- Потенциальный мультипликатор: 8–15x ARR

**Категория B: Медиа и издательства (B2B)**
- Компании, продающие аналитику и отраслевую разведку (Bloomberg, Reuters Eikon, отраслевые аналитики)
- Им интересна: automated intelligence generation + fine-tuned модель для их вертикали
- Потенциальный мультипликатор: 6–10x ARR + стратегическая премия

**Категория C: Корпоративные AI-лаборатории**
- Яндекс, Сбер (через SberDevices), VK — все строят AI-стеки
- Им интересна: команда + опыт в fine-tuning + Frontier-бэкенд как ready-to-deploy кейс
- Структура сделки: acqui-hire + product acquisition

**Категория D: Западные AI-компании с дефицитом нишевых данных**
- Smaller AI labs ищут специализированные датасеты и use cases
- Frontier Intelligence как proof-of-concept "specialized intelligence harness"
- Структура сделки: technology + team acquisition

**Ключевой вывод по M&A:** покупатель Level 3 платит за **flywheel** (данные → модель → пользователи → данные), а не просто за user base. Это принципиально другой разговор на переговорах.

## 6. Execution Principles для Level 3

**Параллельность, не последовательность.** Фазы A, B, C не должны ждать друг друга. Пока SaaS растёт, Data Foundation накапливается автоматически. Пока накапливается — команда ML строит pipeline. Level 3 — это фоновый процесс, не отдельный проект.

**Пользователь не чувствует перехода.** Смена LLM под капотом должна быть незаметной. A/B тест означает: пользователь получает тот же интерфейс, только модель другая. Никаких "мы теперь работаем на своей модели" — только если это улучшает retention (тогда можно сделать маркетинговый момент).

**Claude — это не враг, это страховой полис.** MCP-интеграция остаётся. Power users, которые хотят Claude, получают Claude. Level 3 — это устранение зависимости для 90% use cases, не война с Anthropic.

**Не строить AGI, строить специалиста.** Fine-tuned модель Frontier Intelligence не должна быть "лучше Claude вообще". Она должна быть лучше Claude в задачах харнеса: синтез разведывательных брифов, анализ сигналов, структурированные рекомендации. Узкая специализация = достижимый результат за разумные деньги.
