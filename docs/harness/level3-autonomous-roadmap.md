# Level 3 — Fully Autonomous, Single Window
## Технический Roadmap: от MCP-зависимости к собственному продукту

**Версия:** 1.0  
**Горизонт:** Month 6–30 (параллельно SaaS-треку)  
**Статус:** Стратегический документ, планирование

---

## Зачем этот документ

Level 1 (сейчас) — Frontier-бэкенд + Claude как интерфейс. Anthropic контролирует ключевой слой UX. Level 3 — точка где Frontier Intelligence становится полностью автономным продуктом: собственный LLM, собственный интерфейс, zero внешних зависимостей в критическом пути.

Этот roadmap описывает три фазы перехода. Каждая фаза независима и приносит ценность сама по себе — они не обязаны идти последовательно при наличии ресурсов.

---

## Фаза A — Data Foundation (Month 6–12)

**Цель:** Накопить тренировочный датасет, достаточный для fine-tuning. Заложить инфраструктуру оценки качества.

### A1. Что и как логировать в harness_interactions

Таблица `harness_interactions` — фундамент всего. Минимальная схема:

```sql
CREATE TABLE harness_interactions (
    id              UUID PRIMARY KEY,
    session_id      UUID NOT NULL,
    user_id         UUID NOT NULL,
    mode            TEXT NOT NULL,       -- 'signal_scan' | 'feature_intel' | 'decision_brief' | 'digest'
    user_input      TEXT,               -- запрос пользователя (может быть NULL для scheduled)
    context_json    JSONB,              -- кластеры Frontier, переданные в промпт
    raw_prompt      TEXT NOT NULL,      -- полный промпт (system + user)
    llm_response    TEXT NOT NULL,      -- ответ модели
    model_used      TEXT NOT NULL,      -- 'claude-sonnet-4-5' | 'gpt-4o' | ...
    latency_ms      INTEGER,
    tokens_in       INTEGER,
    tokens_out      INTEGER,
    user_rating     SMALLINT,           -- 1–5, если пользователь оценил
    user_edit       TEXT,               -- если пользователь отредактировал ответ
    implicit_signal TEXT,               -- 'copied' | 'shared' | 'ignored' | 'follow_up'
    created_at      TIMESTAMPTZ DEFAULT NOW()
);
```

**Ключевые правила логирования:**

- Логировать ВСЕ взаимодействия, даже автоматические (брифы, дайджесты) — они золото для обучения
- Фиксировать `implicit_signal`: скопировал ли пользователь ответ, поделился ли, задал ли follow-up вопрос — это дешёвый proxy для качества без явного рейтинга
- Хранить `context_json` — какие сигналы Frontier были "входом" для генерации. Это позволит обучать модель работать именно с Frontier-форматом данных
- Версионировать промпты (отдельная таблица `prompt_versions`) — нужно знать, с каким промптом был получен тот или иной ответ

**Минимальный объём для fine-tuning:**

| Метод | Минимум примеров | Рекомендовано | Примечание |
|---|---|---|---|
| LoRA / QLoRA | 500–1 000 | 3 000–5 000 | Для адаптации стиля и формата |
| Full fine-tune | 10 000+ | 50 000+ | Нецелесообразно на старте |
| RLHF (с рейтингами) | 1 000 пар | 5 000+ пар | Требует explicit feedback |
| DPO (preferred/rejected) | 500 пар | 2 000+ пар | Проще чем RLHF, сопоставимый результат |

**Целевая скорость накопления при 100 активных пользователях:** ~50–100 взаимодействий/день = 1 500–3 000/месяц. За 6 месяцев — 9 000–18 000 примеров. Достаточно для LoRA + DPO.

**Что делать до 100 пользователей (Month 6–9):** синтетические данные. Frontier-сигналы → GPT-4o генерирует "идеальные" ответы → используются как positive examples. Параллельно фиксируются реальные взаимодействия.

### A2. Evaluation Framework

**Проблема:** нельзя просто сравнить BLEU/ROUGE — харнес производит аналитические тексты, не переводы. Нужен специализированный eval.

**Метрики качества для Frontier Intelligence:**

```
Eval Suite v1.0
├── Relevance Score (0–5)
│   Насколько ответ релевантен переданным сигналам Frontier?
│   Оценивает: Judge LLM (GPT-4o) по рубрике
│
├── Actionability Score (0–5)
│   Содержит ли ответ конкретные действия / рекомендации?
│   Оценивает: Judge LLM + keyword checklist
│
├── Novelty Score (0–5)
│   Добавляет ли ответ инсайт сверх того, что было в сырых сигналах?
│   Оценивает: Judge LLM (сравнение с context_json)
│
├── Format Compliance (0/1)
│   Соответствует ли ответ ожидаемой структуре режима?
│   Оценивает: парсер + regex
│
└── Human Preference (win/tie/loss)
    Сравнение пар: собственная модель vs Claude
    Оценивает: blind A/B тест с реальными пользователями
```

**Baseline:** перед запуском fine-tuning прогнать 200 тестовых примеров через Claude. Это reference point. Собственная модель должна побить baseline по Relevance + Actionability при сопоставимом Format Compliance.

**Evals гоняются автоматически** при каждом деплое нового чекпоинта. Регресс >10% по любой метрике = блокировка деплоя.

### A3. Базовые модели-кандидаты

Сравнение по параметрам, важным для Frontier Intelligence:

| Модель | Параметры | Качество (MMLU) | Контекст | Лицензия | Self-host стоимость/мес* | Примечание |
|---|---|---|---|---|---|---|
| **Llama 3.1 8B** | 8B | ~68% | 128K | Llama Community (коммерч.) | ~$150–300 (A100 40GB) | Золотой стандарт open-source на данный момент |
| **Llama 3.1 70B** | 70B | ~83% | 128K | Llama Community | ~$800–1 500 (2×A100 80GB) | Качество близко к GPT-4o, значительно дороже |
| **Mistral 7B v0.3** | 7B | ~64% | 32K | Apache 2.0 | ~$120–250 (A100 40GB) | Свободная лицензия, меньше контекст |
| **Mixtral 8×7B** | ~47B активных | ~77% | 32K | Apache 2.0 | ~$600–900 (2×A100 40GB) | MoE-архитектура, эффективнее 70B |
| **Qwen2.5 7B** | 7B | ~72% | 128K | Apache 2.0 | ~$150–300 (A100 40GB) | Сильнее Llama 8B на ряде задач, хороший multilingual |
| **Qwen2.5 14B** | 14B | ~79% | 128K | Apache 2.0 | ~$300–500 (A100 80GB) | Баланс качество/стоимость |
| **GigaChat** | н/д | н/д | н/д | Проприетарная | API (per token) | Русскоязычный стек, нет self-host |

*Стоимость — ориентировочная, для inference (не обучения), 24/7 uptime.

**Рекомендация для старта:**

- **Phase B MVP:** Qwen2.5 14B — лучший баланс качество/стоимость/лицензия, сильный multilingual (важно для русскоязычного контента), 128K контекст достаточен для Frontier-брифов
- **Phase B Production:** Llama 3.1 70B если eval показывает недостаточное качество 14B
- **GigaChat:** оставить как опцию для специфических русскоязычных клиентов, не основной стек

## Фаза B — Own LLM (Month 12–18)

**Цель:** Запустить собственную модель, способную заменить Claude в inference-пайплайне. A/B тестирование показывает сопоставимое или лучшее качество для профильных задач.

### B1. Fine-tuning Pipeline

```
Данные (harness_interactions)
        │
        ▼
[1] Data Preparation
    - Фильтрация: rating >= 4 OR implicit_signal IN ('copied','shared','follow_up')
    - Очистка: убрать PII, нормализовать формат
    - Форматирование под chat template (Llama/Qwen формат)
    - Train/Val/Test split: 80/10/10
    - Целевой объём: 5 000–10 000 примеров для первого fine-tune
        │
        ▼
[2] QLoRA Fine-tuning
    - Библиотека: Axolotl или LLaMA-Factory (проверенные пайплайны)
    - Метод: QLoRA (4-bit quantization + LoRA adapters)
    - GPU: 1×A100 80GB или 2×A100 40GB
    - Время обучения: ~8–16 часов на 5K примеров
    - Стоимость обучения: $50–150 (RunPod/Modal)
        │
        ▼
[3] DPO Alignment (опционально, Month 15+)
    - Формирование пар: preferred (высокий рейтинг) vs rejected (низкий)
    - Библиотека: TRL (Hugging Face)
    - Цель: выровнять под предпочтения конкретных пользователей
        │
        ▼
[4] Evaluation
    - Прогон Eval Suite v1.0
    - Сравнение с Claude baseline
    - Порог: Relevance ≥ 4.0, Actionability ≥ 3.5, Format 100%
        │
        ▼
[5] Deploy (если eval пройден)
    - Загрузка адаптеров в inference инфраструктуру
    - Shadow mode (1–2 недели): запросы идут в Claude, параллельно запускается своя модель, результаты сравниваются, пользователь не видит
    - A/B mode: 5% → 20% → 50% → 100% трафика
```

### B2. A/B Тестирование

**Принцип:** пользователь не знает, какая модель отвечает. Feature flag на уровне user_id (детерминированное хэширование).

```python
def get_model_for_user(user_id: str, experiment: str) -> str:
    """Детерминированное A/B назначение."""
    bucket = int(hashlib.md5(f"{user_id}:{experiment}".encode()).hexdigest(), 16) % 100
    if bucket < 5:      # 5% — собственная модель (Phase B start)
        return "frontier-qwen-14b-v1"
    return "claude-sonnet-4-5"
```

**Метрики для решения о rollout:**

- Первичные: Relevance Score, Actionability Score из Eval Suite (автоматически)
- Вторичные: implicit_signal distribution (доля 'copied', 'follow_up'), explicit ratings
- Guard rails: latency p95 < 8 сек (vs Claude ~3–5 сек допустимо), error rate < 1%

**Критерий выхода из A/B:** статистически значимое (p < 0.05, n ≥ 500 на каждое плечо) отсутствие деградации по primary metrics. Не обязательно превосходство — паритет достаточен для cost reduction.

### B3. Инфраструктура: варианты и стоимость

**Варианты деплоя (для Qwen2.5 14B, ~8GB в 4-bit, ~16GB в 8-bit):**

| Вариант | Стоимость inference | Latency | Масштабируемость | Операционная нагрузка | Рекомендация |
|---|---|---|---|---|---|
| **RunPod Serverless** | $0.00015–0.0003/token (~$0.30–0.60 per 1M) | 2–6 сек | Авто | Низкая | ✅ Старт (Month 12–15) |
| **Modal.com** | ~$0.00025/token | 1–4 сек | Авто | Низкая | ✅ Альтернатива RunPod |
| **Together.ai** | $0.0002/token (14B) | 1–3 сек | Авто | Нет | ✅ Простейший вариант |
| **Self-hosted (Hetzner/OVH)** | $0.50–1.50/час сервер | 0.5–2 сек | Ручная | Высокая | 🔜 Month 18+ при >$5K MRR |
| **AWS/GCP** | $1.5–4.0/час GPU | 0.5–2 сек | Авто | Средняя | ❌ Дорого для MVP |

**Финансовая точка перехода на self-hosted:**

При 500 активных пользователях × 10 запросов/день × 2 000 tokens/запрос = 10M tokens/день.  
Together.ai: 10M × $0.0002 = $2/день = $60/месяц (дёшево, оставаться).  
При 5 000 пользователях: $600/месяц vs dedicated GPU сервер $800/месяц — граница рентабельности self-host.

**Вывод:** RunPod Serverless / Together.ai до 3 000–5 000 MAU, потом self-hosted.

## Фаза C — Own Interface (Month 18–30)

**Цель:** Пользователь открывает одно приложение Frontier Intelligence — получает всё. Claude остаётся как опция для power users.

### C1. Что такое "собственный интерфейс"

**Три варианта и их трейдоффы:**

| Вариант | Time to build | Стоимость разработки | UX качество | Offline | Рекомендация |
|---|---|---|---|---|---|
| **Веб-чат (PWA)** | 2–3 месяца | $10K–30K | Хороший | Нет | ✅ MVP Phase C |
| **Telegram Mini App** | 1–2 месяца | $5K–15K | Ограниченный | Нет | ✅ Bridge-решение |
| **Мобильное приложение (React Native)** | 4–6 месяцев | $30K–80K | Отличный | Частично | 🔜 Month 24+ |
| **Десктоп (Electron/Tauri)** | 3–5 месяцев | $20K–50K | Отличный | Да | ❌ Нишевый, дорого |

**Приоритет Phase C:**

1. **Month 18–21:** Веб-чат (Next.js + тёмная тема, мобильный responsive) — минимальный own interface
2. **Month 21–24:** Telegram Mini App — встраивается в уже привычный канал доставки (брифы идут в TG)
3. **Month 24–30:** Нативное мобильное приложение (iOS-приоритет, Android параллельно)

### C2. Режимы харнеса в интерфейсе

Каждый режим — отдельный "view" в интерфейсе, не просто chat-промпт:

```
Frontier Intelligence App
│
├── [Dashboard]
│   Живая сводка активных кластеров, emerging signals, дата последнего брифа
│
├── [Signal Scan]
│   Input: тема / домен для мониторинга
│   Output: структурированный список сигналов с source links
│   UI: карточки с тегами, фильтр по давлению/новизне
│
├── [Feature Intelligence]
│   Input: название продукта или конкурента
│   Output: анализ фич, gap-анализ, аналогии
│   UI: comparison table view
│
├── [Decision Brief]
│   Input: вопрос / дилемма для решения
│   Output: структурированный бриф с альтернативами и рекомендацией
│   UI: structured doc view, export в PDF/Notion
│
├── [Weekly Digest]
│   Scheduled, автоматически
│   UI: newsletter-like view, share button
│
└── [Settings]
    Подключение источников, частота дайджестов, языковые предпочтения
    Power user option: "Use Claude via MCP" toggle
```

### C3. Миграция пользователей с Claude Projects

**Риск:** пользователи привыкли к Claude Projects. Смена интерфейса = churn risk.

**Стратегия миграции без оттока:**

**Этап 1 — "Лучшее из двух миров" (Month 18–21):**
- Собственный интерфейс запускается как ДОПОЛНИТЕЛЬНЫЙ канал, не замена
- Ключевое сообщение: "Всё то же самое, но с дашбордом и без необходимости держать Claude открытым"
- Incentive: эксклюзивные фичи доступны ТОЛЬКО в собственном интерфейсе (например, Signal History, сравнение периодов)
- Claude Projects не выключается

**Этап 2 — "Мягкое вытеснение" (Month 21–24):**
- Новые фичи выходят только в собственном интерфейсе
- Claude Projects получает только maintenance updates
- Прямая коммуникация: "Мы строим что-то своё, и вы участвуете в этом"
- Beta program для early adopters: они получают собственный интерфейс первыми

**Этап 3 — "Полная автономия" (Month 24–30):**
- 90% функционала в собственном интерфейсе
- Claude остаётся как "MCP для power users" — явный toggle в настройках
- Маркетинговое переосмысление: "Frontier Intelligence — не Claude-плагин. Это отдельный продукт"

**Метрики успеха миграции:**
- Churn rate в период миграции < 10% (вынужденный churn от тех, кто не готов менять интерфейс)
- WAU в собственном интерфейсе обгоняет WAU в Claude Projects через 3 месяца после запуска
- NPS собственного интерфейса ≥ NPS Claude Projects
