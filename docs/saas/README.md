# Frontier Intelligence → SaaS: пакет проектирования

> **Статус:** проект / план. Это **только документация** — код и существующие файлы не изменялись.
> **Дата:** 2026-06-26 · Сгенерировано многоагентным анализом текущей сборки (Cursor/Claude).

Этот каталог описывает превращение Frontier Intelligence из персональной одно-операторской
системы тренд-аналитики в **многотенантный SaaS** для RU-рынка (международные платежи — позже),
с сохранением LLM-провайдеров **Wormsoft (основной) → OpenRouter → Polza → GigaChat**.

## Зафиксированные решения владельца (вход для всего проекта)

| Решение | Выбор | Главное следствие |
|---|---|---|
| Продуктовая модель | **Гибрид**: курируемые потоки + ограниченный self-serve | Telegram — только платформенно-курируемый; self-serve — RSS/web/api с SSRF-защитой и квотами |
| LLM-ключи | **Платформенные** + per-tenant учёт | Биллинг строится поверх существующей FinOps/credit-guard инфраструктуры |
| Эквайринг RU | **YooKassa (ЮKassa)** | Рекуррент + вебхуки; абстракция платежей под международную фазу позже |
| Юрстатус | **Самозанятый (НПД)** | Потолок **2.4 млн ₽/год**, **нельзя нанимать**, чеки НПД через «Мой налог»/YooKassa (не 54-ФЗ ККТ). Юрлицо ещё не оформлено → регистрация = предусловие платного запуска |
| Тенантность *(раунд 2)* | **Аккаунт владеет многими workspace** | Курируемые потоки — общие (`account_feeds`); кастомные — приватные (`account_workspaces`) |
| Биллинг *(раунд 2)* | **Фикс-план + включённая квота + soft/hard overage** | Двухуровневый контроль: per-tenant квота + глобальный потолок провайдера |
| Хостинг/egress *(раунд 3)* ✅ | **Один зарубежный регион + residential-прокси для Telegram** | xray HTTP-failover удаляется; 152-локализация вынесена за скобки владельцем; см. [11](./11-hosting-residency-egress.md) |
| Embeddings *(раунд 3)* ✅ | **Wormsoft `qwen3-embedding:8b`** (4096d, multilingual) | один реиндекс Qdrant закрывает и уход с GigaChat, и международную фазу; open-weights → портируемо |

**Стратегическая рамка:** НПД-потолок + запрет найма ⇒ ставка на **небольшое число дорогих
B2B-подписок**, всё **solo-operable** (автоматизация-first), с жёстким guardrail по выручке и
задокументированным переходом в ИП/ООО при масштабировании.

## Заголовочные находки

**Готово к SaaS (переиспользуем):** аналитическое ядро, 5 курируемых потоков + ~64 источника,
~30 MCP-инструментов поверх рабочего SSE-гейтвея `:8102`, мульти-LLM роутер с платформенными
ключами, FinOps-схема (`ExecutionReceipt`/`cost_workspace`) уже tenant-aware.

**Блокеры до первого платного клиента:** (1) нет модели идентичности; (2) нулевая
аутентификация на всех трёх поверхностях, `workspace` — недоверенный параметр; (3) нет платежей;
(4) per-tenant метеринг — «мёртвый код» (`workspace_id` не доходит до LLM-вызовов); (5) нет
долговременного ledger потребления; (6) «стоимость» в токенах, не в рублях; (7) нет
per-tenant квот.

**Порядок (из дорожной карты):** сначала дёшево и важно — Фаза 0 «security lockdown»
(закрыть auth/CORS, увести admin за VPN) и активация метеринга; затем тенантность+биллинг;
затем self-serve источники; затем HA/DR-усиление.

## Что НЕ сделано в этом пакете

- Не написан ни один реальный код, не изменены существующие файлы (`docker-compose.yml`,
  схемы, сервисы) — только новые документы в `docs/saas/`.
- DDL и последовательности изменений в доменных файлах — **проектные эскизы**, требуют
  ревью перед реализацией.
- Пункты с пометкой «проверить у бухгалтера/юриста» (механизм НПД-чеков, 152-ФЗ/РКН,
  лицензирование перепродаваемых фидов) — вне компетенции этого анализа, см. [10-decision-log](./10-decision-log.md).
